# MediaForge 创作者真人验收与整改报告

> 日期：2026-08-10  
> 结论：**R0 创作者主路径未通过，暂停 R10 及后续扩展，先完成本报告的 P0 整改。**  
> 验收方式：只使用浏览器页面完成输入、点击、等待和观察；没有调用项目 API、CLI 或脚本替代创作者操作。  
> 本轮范围：只做体验验收和整改处方，不修改产品代码，不进行真实发布。

## 1. 一句话结论

MediaForge 已经拥有研究、版本、图片、平台适配、审批和安全导出等后台能力，但它仍然把这些能力组织成一条需要用户维护的流水线。创作者真正想完成的是“写出并看见一篇文章”，当前产品要求他先理解项目、研究板、主稿、视觉、平台版本、审批和 ZIP。

因此，这不是继续优化卡片、颜色或按钮文案能解决的问题。需要把产品中心从“流程状态”改成“正在创作的文章”。

## 3. 已确认的直接技术原因

这些不是推测，均可由当前源码和浏览器行为对应。

### P0-1：前端更新后旧页面会静默失效

- 浏览器记录到旧页面请求已经不存在的 `ProjectCreate-Cf03RTUc.js`。
- SPA 的 `index.html` 返回没有显式 `Cache-Control: no-cache`，见 `pipeline/webui/app.py` 的 catch-all。
- 路由懒加载失败没有全局错误边界、自动刷新或“版本已更新”提示。

结果是用户点击关键按钮时什么都没有发生。用户无法判断是自己不会用、网络失败，还是产品更新了。

### P0-2：“AI 先起草”只是保存的元数据，不控制交互

`frontend/src/views/ProjectCreate.vue` 让用户选择四档自主程度，但创建成功后所有模式都进入同一研究工作台。自主程度虽然进入 Project 和 LLM prompt，却没有改变用户的第一步。

用户选择“AI 先起草”后仍被要求手工录入研究板，这属于产品承诺和行为不一致。

### P0-3：初稿按钮存在隐藏硬门槛

`frontend/src/views/Projects.vue` 中 `researchReady` 要求：

- 至少 3 个来源；
- 至少 1 条个人判断；
- 没有未核查事实；
- 没有待解决问题。

初稿按钮直接使用 `:disabled="!researchReady"`，但页面没有把这四个条件显示在按钮旁，也没有说明每项如何完成。更根本的问题是：这套标准适合发布前事实检查，不应该成为个人观点文章开始写作的门槛。

### P0-4：错误状态会替换整个工作台

`frontend/src/views/Projects.vue` 使用：

```vue
<a-alert v-if="detailError" />
<article v-else-if="project">...</article>
```

任何局部操作错误都会让整个项目工作台消失。视觉计划的必填校验已经真实触发了这个问题。

### P0-5：完成结果仍是表单，不是文章

平台稿以标题输入框、摘要 textarea 和正文 textarea 呈现。锁定后这些控件只是变成 disabled。系统有预览 HTML 能力，但 UI 用 `window.open('/api/.../preview')` 把它放在原始 API 地址和弹窗行为后面，没有应用内阅读路由、加载状态、失败反馈或返回路径。

### P1-1：ZIP 被放在了产品完成态

ZIP 对程序备份和跨系统传输有价值，但它不是创作者心中的作品。当前审批完成后，界面最明确的产出动作是“导出 ZIP”，这会把工程交付物错误地提升为用户结果。

### P1-2：首页失去“开始新文章”的入口

`frontend/src/views/Today.vue` 只有在完全没有项目时才显示“新建创作项目”。只要已有一个项目，首页主按钮就只剩“打开工作台”。这让“继续旧项目”压过了“产生新作品”。

## 4. 第一性原理诊断

### 4.1 创作者购买的是作品，不是流程

一个创作者进入系统时，只有四个核心问题：

1. 我想写什么？
2. AI 能怎样帮我？
3. 现在这篇文章长什么样？
4. 我怎样把它带到目标平台？

当前页面首先回答的却是：项目处于哪个阶段、研究是否达标、版本是否锁定、审批是否 stale、导出包是否生成。

这些概念有工程价值，但不应成为第一层交互。

### 4.2 安全检查被提前成了创作许可

事实核查、版本锁定、审批和防覆盖都应该保留，但应当在对应风险出现时工作：

- 写作时允许不完整，标记事实风险；
- 生成平台稿时提醒缺失材料；
- 交付前执行严格检查；
- 发布前要求人工确认。

当前产品把交付标准提前放到了起稿之前，所以安全能力变成了创作阻力。

### 4.3 对象模型泄露给了用户

Idea、Project、Research、Master、Visual、Variant、Approval、Export 是合理的数据边界，不应一一对应成用户必须理解的页面和步骤。

它们应当服务同一张创作桌面。用户修改的是文章，系统在后台维护这些对象。

### 4.4 旧流水线只是被重新命名

主导航虽然已经从 `ingest / score / gate` 改为创作者语言，项目内部仍然是固定的 1-5 阶段驾驶舱。这正是用户感受到“还有以前影子”的原因。

产品重启计划本身已经写明“以主稿编辑器为中心，而不是继续使用多页向导”，但实际实现仍以阶段切换为中心。这一轮应当落实原计划，而不是再做一次表面换肤。

## 5. 新的产品中心

### 5.1 一句话产品定义

> 打开就是文章。输入一个想法后，AI 和资料、图片、平台适配都围绕这篇文章出现。

### 5.2 建议的工作台

```text
┌ 返回 / 文章标题 / 已保存 / 预览 / 生成平台稿 ─────────────────┐
│                                                              │
│  资料与大纲           正在写的文章             AI 创作助手     │
│  可折叠抽屉           标题                     下一步建议       │
│  来源                 封面                     改写/扩写        │
│  事实提醒             正文与行内图片           配图/换图        │
│                       实时阅读预览             平台适配         │
│                                                              │
├ 主稿预览 | 微信公众号 | 今日头条 | 更多操作 ─────────────────┤
└──────────────────────────────────────────────────────────────┘
```

默认只显示文章和一个明确动作。研究、版本、视觉元数据和审批历史放进抽屉或“更多”，需要时再出现。

### 5.3 新的最短路径

1. 首页点击“写新文章”。
2. 输入一句想法或粘贴一段材料。
3. 选择“我先写”或“AI 先写”。
4. 直接进入文章编辑器。AI 模式在同一页生成可审阅初稿；人工模式已经可以输入正文。
5. 文章成形后点击“加封面和插图”，AI 根据正文提出并生成视觉方案。
6. 点击“生成平台版本”，一次生成微信和头条，使用两个预览标签切换。
7. 完成页首先展示可阅读成品。复制、下载 Markdown、下载 HTML、ZIP 备份放在次级操作中。

## 6. 整改任务

## P0：必须先完成

### P0-A：修复版本更新导致的静默失效

- `index.html` 使用 `Cache-Control: no-cache`；hash 资产可使用长期 immutable 缓存。
- 为路由动态 import 失败增加全局恢复：识别 chunk 加载错误，只自动刷新一次；仍失败则显示“页面已更新，点击刷新”。
- 所有按钮异步失败必须在按钮附近或当前区域显示，禁止静默无响应。
- 验收时必须先打开旧构建页面，再替换 dist，确认下一次点击能恢复或明确提示。

### P0-B：让自主程度真正控制第一步

- 把四档选择收敛为两种可理解的起点：“我先写”和“AI 先写”。
- 暂时隐藏“AI 准备内容包”，直到它能从一次显式点击真实完成整包。
- “AI 先写”下，点击创建就是一次明确的 AI 授权。创建 Project 后立即在文章页启动可审阅初稿，不能再落到手工研究表。
- AI 失败时保留项目和输入，并提供“重试”与“先自己写”。

### P0-C：取消研究对起稿的硬阻塞

- 删除 `researchReady` 对“AI 初稿”按钮的禁用关系。
- 研究完整度继续用于交付前检查，不能用作写作许可。
- 个人观点文章允许 0 个来源起稿；事实型文章允许先起草结构，但必须把事实陈述标成“待核查”。
- 如果按钮禁用，旁边必须显示全部未满足条件和直接修复动作。不得出现无解释的 disabled CTA。

### P0-D：将项目默认页改成文章编辑器

- 进入 `/projects/:id` 时默认展示主稿，不再默认展示第一项未完成流程。
- 没有主稿时显示一个大输入区和唯一主动作；有主稿时显示正文、保存状态和阅读预览。
- 1-5 步骤条改成次级状态摘要，或完全移入“项目检查”。
- 拆分当前超大 `Projects.vue`，至少形成项目壳、文章编辑器、资料抽屉、视觉面板、平台预览、交付检查六个可独立测试的组件。

### P0-E：错误不再清空工作上下文

- `detailError` 不能再与整个 `project-workspace` 互斥。
- 表单校验显示在对应字段下；请求错误显示在对应区域；全局错误以可关闭通知呈现。
- 任一错误后，标题、正文、视觉计划和当前滚动位置仍在。
- 视觉默认方案必须自带可保存的视觉风格，或者把视觉圣经改成可选并由 AI 从文章声音推导。

### P0-F：把文章阅读态变成应用内一级页面

- 新增应用内预览路由，例如 `/projects/:id/preview?platform=wechat_mp`，不要把原始 API HTML 作为主要用户入口。
- 完成项目、平台标签和首页最近成品都能直接进入阅读态。
- 阅读态必须渲染标题、摘要、封面、正文层级、引用链接和行内插图。
- 预览失败要有加载、错误、重试和返回编辑器，不依赖浏览器弹窗。
- 平台稿编辑应使用“编辑 / 预览”切换，不要把 disabled textarea 当成成品展示。

### P0-G：完成态首先交付作品

- 审批完成后主动作改为“查看成品”。
- 次动作是“复制微信公众号稿”“复制头条稿”或安全草稿箱交付。
- Markdown、HTML、图片和 ZIP 放进“下载与备份”。
- ZIP 保留，但不能再作为完成这篇文章的视觉终点。

## P1：P0 通过后完成

### P1-A：简化创建页

- 默认只要求“想写什么”；标题可以从首句生成，也可以随后修改。
- 受众、目标、声音改为可选的“帮助 AI 更懂你”，提供合理默认值。
- 首页无论是否已有项目，都始终显示“写新文章”。
- 灵感提升和直接新建最终进入同一文章页，不能形成两套心智。

### P1-B：研究变成资料抽屉

- 来源录入支持直接粘贴 URL、文本或本地笔记，不先要求拆成标题、引用和摘要三个字段。
- AI 可以提取候选摘要和声明，但必须由人确认，不能伪装为已核查。
- 用正文旁的标记展示“此句待核查”“缺少来源”，而不是要求用户先维护完整声明数据库。

### P1-C：视觉围绕文章段落出现

- 主稿成形后，由 AI 一次提出封面和 2 张插图的位置、用途和 prompt。
- 用户在文章上下文内生成、编辑、选择和换图。
- 视觉圣经、模型版本、预估成本和失败审计保留在详情面板，不占据主创作路径。

### P1-D：双平台一次生成、分别编辑

- 一个“生成平台版本”动作同时准备微信和头条，随后用标签切换。
- 保留独立版本、锁定、上游 stale 和恢复能力，但把版本管理放到历史面板。
- 只在主稿更新且平台稿有人工修改时提示合并，不要求用户主动点击“检查主稿更新”。

### P1-E：审批降级为交付检查

- 系统自动检查缺图、短文、未核查事实、平台稿 stale 等客观项。
- 用户只做一次清晰的最终确认；审批人、逐项备注和历史记录放在“审计详情”。
- 真实发布仍必须遵守现有安全开关和人工确认，不得借本次 UX 整改放宽发布红线。

## 7. 建议删除或隐藏的当前交互

- 项目首屏的 1-5 固定流程驾驶舱；
- “AI 初稿”前必须恰好 3 个来源的硬门槛；
- 尚未真实实现的一键“AI 准备内容包”选项；
- 同时出现“AI 适配平台初稿”和“创建平台初稿”的重复按钮；
- 完成页主区域的审批 actor、四组备注输入和长历史流水；
- 以禁用表单展示已完成文章；
- 把 ZIP 作为主要完成动作；
- 项目头部“已关联 0 篇内容，0 项资产”这类内部聚合信息。

底层存储、审计、版本、stale、原子写和安全导出能力不删除，只改变它们的展示层级。

## 9. 必须使用浏览器完成的验收剧本

任何 API 测试、组件测试和构建成功都不能替代下面的真人路径。

### 剧本 A：AI 先写

1. 从“今天”点击“写新文章”。
2. 只输入一段 50-200 字的真实想法。
3. 选择“AI 先写”并创建。
4. 90 秒内在同一页面看见可编辑、可拒绝的初稿。
5. 全程不要求先录入 3 个来源，不出现无解释禁用按钮。
6. AI 失败时输入和项目仍在，并可重试或转为手写。

### 剧本 B：我先写

1. 输入一句想法并选择“我先写”。
2. 创建后焦点直接位于正文编辑器。
3. 保存、刷新后内容仍在。
4. 选中一段请求 AI 改写，拒绝后正文不变，接受后形成新版本。

### 剧本 C：图文成品

1. 在已有主稿点击“加封面和插图”。
2. 系统提出 1 张封面和 2 张插图方案，不要求用户先发明“视觉圣经”。
3. 生成、选择后，图片立即出现在文章阅读预览的正确位置。
4. 错误发生时文章和视觉表单不消失。

### 剧本 D：双平台和完成态

1. 点击一次生成微信和头条版本。
2. 两个平台在预览标签中分别可读、可编辑。
3. 修改微信稿不会覆盖头条稿。
4. 完成后首先看到文章，不是 textarea、审批历史或 ZIP。
5. ZIP 只能从“下载与备份”找到。
6. 不创建 Publication，不触发真实发布。

### 剧本 E：前端版本更新

1. 保持一个旧构建页面打开。
2. 更新前端 dist。
3. 点击懒加载路由。
4. 页面自动恢复一次，或明确显示“页面已更新”并提供刷新按钮。
5. 不允许静默无响应。

## 10. 完成定义

P0 只有同时满足下列条件才算通过：

- 第一次使用者从一个想法到看见可编辑初稿不超过 3 个主点击；
- 创建文章时必填输入不超过 2 项；
- 任何时刻都能回答“我的文章在哪里”；
- 文章默认以可写或可读形态出现，不以禁用表单出现；
- 没有无解释的 disabled 主按钮；
- 任一局部错误都不会清空整张工作台；
- 完成态主动作是查看文章，ZIP 只是备份；
- 上述 A-E 全部由浏览器真实点击走通并留存时间线；
- Python 全量测试和前端构建保持绿色；
- `publish.enabled=false`，没有真实发布副作用；
- 用户本人再次进入系统，可以不读说明完成一篇文章，并明确表示愿意继续使用。

最后一条是产品验收，不得由模型代签。
