## 1. 这份文件解决什么问题

MediaForge 已经有项目 sidecar、研究资料、主稿版本、图片、平台稿、审批、导出和发布安全等能力，但用户多次真人试用后仍然无法自然完成创作。旧系统的主要问题不是“能力少”，而是把后台流水线直接暴露成了创作者的操作流程。

这份文件把访谈中已经确认的产品事实固化下来，作为下一轮产品设计的输入。它不证明任何功能已经实现，也不授权模型立即改代码。

文中使用四种标记：

- **已确认**：产品所有者已经明确表达或认可，后续不得擅自改回旧方向。
- **产品推导**：根据已确认目标得出的设计结论，可以在评审时继续调整。
- **现状事实**：仓库或真人验收已经证明的当前状态。
- **待决定**：还需要产品所有者在看到原型或真实结果后拍板。

## 2. 一句话产品定义

> **MediaForge 是 AI 原生的个人创作工作台：创作者给出一个主题、自己的想法和可选参考材料，AI 直接生成一篇带封面和上下文插图的完整文章；创作者可以像批注文档和审查代码 diff 一样提出局部或整体意见，确认修改后，再按账号和平台完成适配、导出与安全发布。**

产品同时保留第二条路径：一个专注具体赛道的 AI 创作账号可以自主发现选题、研究、创作和准备发布，但它必须向用户提供足够的决策依据，并服从用户的价值观、确认权和发布安全边界。

## 3. 北极星结果

### 3.1 个人创作

**已确认**：用户打开首页，首先看见个人创作输入区，而不是“今天 / 灵感 / 项目”导航、流水线步骤或统计面板。

最短路径是：

1. 输入主题和自己的描述、想法；
2. 可选添加图片、文章链接、PDF、Markdown 等参考；
3. 点击一次“生成文章”；
4. 在同一工作区直接看见一篇可阅读、可编辑的图文成品草稿；
5. 对局部或整篇提出意见，审阅 AI 修改前后差异；
6. 确认最终稿；
7. 选择平台账号，预览平台版本，并按平台能力立即发布或使用平台原生定时发布；
8. 需要时导出 Markdown。

### 3.2 自动化创作

**已确认**：自动化不是个人创作流程里的一个复杂“自主程度”选项，而是另一条独立入口。

自动化路径中，一个 AI 创作账号长期专注一个赛道，完成：

1. 发现候选选题和爆款信号；
2. 给出用户能判断的证据和建议；
3. 在用户选择参与时接收调整，用户不参与时按授权继续；
4. 复用与个人创作相同的文章、批注、版本、图片、平台适配和安全交付能力；
5. 发布能力逐步从人工确认走向受监督自动化，不得一开始就无人值守真发。

### 3.3 成功标准

产品成功不以“支持多少平台、生成多少文件、后台有多少阶段”衡量，而以这些问题衡量：

- 用户进入首页后，是否一眼知道从哪里开始；
- 从输入想法到第一次看见完整图文草稿，是否只需要一次主要操作；
- 用户是否始终知道“我的文章在哪里”；
- AI 的每次正文修改是否可定位、可比较、可拒绝、可撤销；
- 文章是否像成品，而不是若干表单、占位符或 ZIP；
- 平台适配和发布是否尊重账号能力、安全门和用户最终确认；
- 产品是否真实节省用户时间，并逐步帮助形成影响力和可持续收入。

## 4. 用户与创作者身份

### 4.1 作者对外定位

**已确认的作者介绍**：

> 前大厂程序员。用做产品和体育的方式体验生活，也在真实测试：普通人如何与 AI 一起重新建立工作、收入和自由。

### 4.2 可以使用的真实背景

- 前大厂程序员；
- 爱体育、爱生活；
- 有滑雪、攀岩、游泳教练相关证书；
- 有 AOW 潜水证和无线电执照；
- 做过约一个月游泳教练；
- 正在围绕自己的真实需求做和维护多个小产品，MediaForge 会继续维护。

这些经历用于提供真实观察和叙事素材，不得包装成职业级体育专家、潜水专家或人生导师。用户本人已经明确说明部分证书取得不难、技术水平普通，文章必须保持诚实。

### 4.3 默认不公开的信息

下列内容虽然是理解创作动机的重要背景，但默认属于私密信息，只有用户针对具体文章显式同意后才能使用：

- 离职后在家带孩子的具体年限；
- 家庭成员施加的压力；
- 房产损失、现金紧张等具体财务状况；
- 其他可识别家庭成员或造成家庭困扰的细节。

可以抽象表达“希望增加收入、让生活更有安全感”，但不得用隐私换取冲突感和流量。

### 4.4 写作方式

**已确认**：个人写作不适合被周更、日更或内容 KPI 绑架。用户会在真正有想法、有体验时写；AI 和自动化负责降低整理、研究、改写、配图、适配和发布的重复劳动。

## 5. 初始内容方向

### 5.1 核心赛道

**已确认的初始定位**：

> **普通人的 AI 工作与增收实验室：不追参数，不制造焦虑，用真实任务验证 AI 怎样节省时间、改善工作并创造额外收入。**

平台是分发渠道，不是赛道本身。当前可以先从微信公众号和头条验证，但未来不局限于这两个平台。

### 5.2 典型读者

首要读者是 27—39 岁左右、非纯技术背景的知识工作者、自由职业者和小生意经营者，例如运营、销售、市场、行政、产品、教育、创作者和小企业主。他们已经知道或试过 AI，但没有形成稳定、可复用的工作方式。

年龄与职业分布是初始用户假设，不应伪装成已有调研数据；后续要用真实内容数据和读者访谈校正。

### 5.3 核心痛点

- 工具很多，不知道哪一个真正解决自己的问题；
- AI 输出看似完整，最后仍要大量重写；
- 天天使用 AI，却没有因此更早下班或更轻松；
- 担心被替代，但不知道该学习什么、怎样建立新能力；
- 想做副业、个人品牌或小产品，却缺时间和稳定方法；
- 担心事实错误、隐私泄露和明显的“AI 味”；
- 只有零散技巧，没有能反复运行的工作流。

### 5.4 内容结构假设

作为第一阶段的产品推导，可以使用：

- 50%：普通人的日常工作与 AI 实验；
- 30%：职业变化、能力重建和生活选择；
- 20%：真实的小产品、服务和增收实验。

这不是强制排期。个人创作仍由真实灵感驱动，自动化账号可把它作为候选选题的组合约束。

### 5.5 可优先验证的主题

- 为什么你每天都在用 AI，却没有因此早点下班？
- 我把“全自动内容流水线”做复杂了以后，为什么自己反而不会用？
- 普通人真正需要的不是更多 AI 工具，而是一条能完成工作的路径。
- 用 Git 管理个人知识是否值得：当前只能写成计划、设计和搭建过程，不能假装已经长期运行成功。
- 从真实生活需求出发做小产品：哪些真的留下来了，哪些只是自我感动。

## 6. 输入与资料

### 6.1 一次创作的输入

**已确认**：最低输入是“主题 + 自己的一些描述和想法”。所有其他信息都是可选增强项，不得成为开始写作的硬门槛。

可选参考包括：

- 图片；
- 文章链接或网页；
- PDF；
- Markdown；
- 纯文本、粘贴笔记；
- 后续可扩展的其他文件。

每项资料都要有独立的读取状态和失败提示。单个链接或文件失败不能清空其他输入，也不能阻塞用户先写。

### 6.2 资料与事实边界

- AI 必须区分来源事实、作者观点和待核查结论；
- 引用或关键事实能够回到原始来源；
- 不可读取的资料必须明确标记，不能假装已经使用；
- 没有可靠数据时不得编造流量、收入或平台表现；
- 资料完整度影响交付检查，不影响创作启动。

### 6.3 `writing-materials` 的定位

[writing-materials](https://github.com/toolazytoname/writing-materials) 是已有素材种子，包含技术方案、部署实录、踩坑记录和文章原料。它可以为首批内容提供真实材料，但当前不能写成已经建成的长期知识库。

**已确认现状**：长期知识库仍在筹备中，尚未开始建设。《我为什么用 Git 管理个人知识，而不是继续付费买笔记软件》目前是计划和想法，不是已经完成并长期验证的案例。

### 6.4 未来知识层

未来可以形成三层结构：

```text
Raw 原始来源（不可变）
        ↓
Wiki / Knowledge（AI 持续维护、交叉引用、标记矛盾）
        ↓
Article Project（一次具体创作及其版本、图片和平台稿）
```

这是已认可的长期方向，但不是个人创作首个可用版本的前置条件。必须先让“输入材料 → 完整文章”跑通，再单独做知识库 RFC 和实现。

## 7. 文章工作区

### 7.1 默认状态

**已确认**：生成完成后，页面中央首先呈现文章本身，包括：

- 标题；
- 封面；
- 正文层级；
- 嵌在正确上下文位置的插图；
- 引用和必要的事实提示；
- 清楚但不过度打扰的保存/生成状态。

Project、Research、Master、Visual、Variant、Approval 等后台对象不删除，但不得成为创作者需要按顺序理解的主导航。

### 7.2 成品级图文

封面和插图不是独立资产列表，也不是 `[IMAGE: ...]` 占位符。它们应出现在文章上下文中，与相邻段落的内容和表达目的相关联。

每张图至少保留这些后台信息：用途、关联段落、生成或来源信息、prompt、版本、当前选择、失败记录、预估成本。普通创作页面默认只显示图片和直接可用的“换图 / 修改 / 删除”操作。

### 7.3 手动编辑

用户可以直接修改标题、正文、图片说明和必要的排版。保存不能静默覆盖最后一个可恢复版本。

## 8. 反馈、批注和 AI 修改

### 8.1 两种意见

**已确认**：

- 整篇意见：例如“更克制一些”“不要像教程”“核心观点不够鲜明”；
- 局部意见：选中一句、一段、一个标题或一张图片，针对该位置评论。

局部交互应接近文档批注或“圈出来说怎么改”，而不是让用户复制段落到另一个聊天框。

### 8.2 修改提案

AI 不直接覆盖正文。每次修改先形成提案，再以类似 Beyond Compare 或 Git diff 的双栏视图呈现：

- 左侧：当前正式版本；
- 右侧：AI 建议版本；
- 清楚显示新增、删除、替换和受影响图片；
- 显示本次意见、作用范围和 AI 的必要说明；
- 用户可以继续手动调整右侧建议稿；
- 用户可以整次接受、整次拒绝，后续再支持按修改块接受；
- 点击确认后生成新的正式版本，旧版本仍可恢复。

### 8.3 图片反馈

用户可以直接针对封面或插图提出意见，例如“人物太像广告”“换成居家真实场景”“保留构图但减少文字”。图片修改也需要候选、选择和版本，而不是覆盖原图。

## 9. 平台、账号与交付

### 9.1 平台版本

同一篇主稿可以生成多个平台原生版本，但不是把同一份文本机械复制到所有平台。

- 微信公众号：适合更完整的论述、信任积累和长期沉淀；
- 今日头条：适合发现流量、强切入和面向更广泛读者的解释；
- 知乎、小红书、Bilibili、视频号等可以后续按真实收益和能力选择，不在首个个人图文闭环里同时铺开。

平台版本可以独立编辑，修改一个平台不得覆盖另一个平台或主稿。

### 9.2 最终确认页

**已确认**：最终确认时至少显示：

- 将要发布的文章预览；
- 平台名称和渠道名称；
- 账号名称；
- 该平台是否支持立即发布、草稿箱或原生定时发布；
- 选择的发布时间和时区；
- 仍存在的事实、图片、平台限制或账号风险；
- 明确的最终确认动作和可审计回执。

### 9.3 定时发布的准确含义

**已确认**：“定时发布”是把用户选择的时间传给目标平台已经提供的定时发布功能，不是在 MediaForge 本地创建 cron、后台定时任务或到点再模拟点击实时发布。

因此每个平台必须明确区分：

- 支持平台原生定时；
- 只支持保存草稿；
- 只支持立即发布；
- 当前接口或账号权限无法确认。

不支持时必须如实说明，不能用本地调度伪装成平台原生能力。

### 9.4 导出

- 应用内“查看成品”是主要完成态；
- Markdown 导出是正式能力；
- HTML、图片包和 ZIP 可以作为次级下载、迁移和备份；
- ZIP 不能再成为用户完成一篇文章后的主要结果。

### 9.5 发布安全

目标产品会支持选择账号后直接发布，但当前阶段仍遵守既有红线：

- 本文档不授权真实发布；
- 在平台能力、账号、预览、审批和幂等保护未通过真人验收前，只允许 dry-run、草稿箱或安全导出；
- 任何真实发布必须由用户另行显式授权；
- 既有 `safe_publish`、白名单、锁、防重复、审计和不静默覆盖能力继续保留。

## 10. 自动化创作的决策信息

**已确认目标**：自动化账号可以少让用户操作，但当用户参与选题时，必须提供足够信息帮助判断“有没有流量、是否可能成为爆款、是否有价值、是否符合我的价值观”。

候选选题卡应尽量提供：

1. 为什么现在值得写：事件、趋势或读者问题的时效性；
2. 流量证据：搜索、平台热度、相似内容表现或其他可验证信号；
3. 典型读者和具体痛点；
4. 最强切入点、标题钩子和冲突；
5. 读者读完能获得的实际价值；
6. 与账号定位和作者真实经历的匹配度；
7. 我们能提供、而同类内容缺少的独特角度；
8. 是否符合价值观及潜在风险；
9. 同类内容拥挤度和时间窗口；
10. 需要的资料、时间、图片和制作成本；
11. AI 建议、置信度、反方理由和仍待确认的事实。

用户可选择“开始创作 / 调整角度 / 稍后 / 放弃”。系统可以从这些选择中提出账号偏好更新，但只有用户确认后才能写入长期策略。

## 11. 收入与产品生态

### 11.1 现实目标

用户希望逐步增加收入，让生活更有安全感。月入几千元可以作为希望验证的阶段性商业目标，但不是产品或内容能够保证的结果。

### 11.2 内容与产品的关系

**已确认**：优先创作自己生活中真正会用到的产品和服务。用户的 [GitHub](https://github.com/toolazytoname/) 及其中多个持续维护项目，可以构成真实实验和内容来源，但不得强行把所有项目塞进同一个产品。

MediaForge 的角色尤其明确：它既是要持续维护的产品，也是作者自己每天用来生产内容、检验 AI 协作方式的“内容操作系统”。最有说服力的内容来自真实使用、失败、修复和结果，而不是伪造成功案例。

### 11.3 商业边界

- 不承诺收入；
- 不为变现推荐自己并未使用或不相信的产品；
- 先验证内容信任和真实需求，再测试工具、服务、模板、咨询或其他商业形态；
- 任何转化数据必须可追踪，不能用虚荣指标代替收入和用户价值。

## 12. 内容价值观与红线

以下原则已经确认，个人创作和自动化账号都必须遵守：

- 不夸大收入，不承诺稳赚或固定结果；
- 不通过制造失业、年龄或家庭焦虑博眼球；
- 不把未经验证的判断写成事实；
- 不暴露家庭隐私；
- 不把股票、加密资产等高风险内容写成投资号召；
- 不攻击具体个人，不靠羞辱制造冲突；
- 不伪装自己使用过某产品、做过某实验或取得过某成绩；
- 不伪造数据、引用、读者反馈、平台回执和账号能力；
- 不抄袭，尊重来源与版权；
- 遵守各平台关于 AI 内容、版权、广告和发布的现行规则。

| 首页是“今天”，从灵感、项目、资产等导航开始 | 首页直接是个人创作输入；历史项目和其他能力退到次级入口 |
| 创建时选择四档自主程度 | 个人创作只有一次明确生成；自动化创作是独立路径 |
| 进入项目后按研究、主稿、视觉、平台、审批逐步操作 | 默认打开文章；后台对象围绕文章按需出现 |
| 先准备足够研究资料才能起稿 | 最低只需主题和想法；资料可选，风险在正文和交付阶段标记 |
| 图片在单独资产阶段生成 | 封面与插图嵌入文章上下文，在文章里换图和评论 |
| AI 改写通过聊天或直接写回 | 局部/整体批注 → 双栏 diff → 人工确认 → 新版本 |
| 完成意味着导出 ZIP | 完成意味着看见成品；Markdown 正式导出，ZIP 仅备份 |
| 本地定时任务到点触发发布 | 只适配平台原生定时能力，不伪装成本地调度 |
| 长期知识库已经存在 | 只有素材种子；知识库仍是待 RFC 和实现的未来能力 |
| P0-A—P0-G 代码完成就代表产品通过 | 这些实现是可复用候选；用户仍不会用，因此必须按本文重新验收和重构 |

旧整改报告中的缓存恢复、局部错误、应用内预览、文章优先、ZIP 降级等方向继续有效；“我先写 / AI 先写”的创建模式和“今天 / 灵感 / 项目”的首页心智已经被本次访谈进一步修订。

## 14. 已有能力如何处置

### 保留并复用

- Project / Research / Master / Visual / Variant / Approval sidecar；
- 原子写、严格校验和路径保护；
- 正文、图片和平台稿版本；
- AI 修改可接受、拒绝和恢复；
- 平台稿独立编辑与 stale 检测；
- 审批、安全导出、防覆盖、防重复发布和发布锁；
- 本地、gitignored、权限受限的模型密钥设置。

### 移出主路径

- 固定阶段驾驶舱；
- 研究、视觉圣经、版本号、锁和审批 actor 等工程概念；
- 开发者运行状态和内部 stage；
- ZIP 交付物；
- 平台和账号后台管理细节。

### 暂不扩展

- 视频和数字人；
- 一次接入大量新平台；
- 多账号矩阵和无人值守真实发布；
- SQLite schema 迁移；
- 把长期知识库当作个人创作的前置依赖。

## 15. 仍待产品所有者后续拍板

这些问题不阻塞把文档固化下来，但实现前或原型评审时仍需决定：

1. 首页个人输入区的最终视觉形态，以及自动化入口在首页的层级；
2. 第一版附件的文件大小、页数和类型上限；
3. 双栏 diff 第一版是否必须支持“按修改块接受”，还是先整次接受/拒绝；
4. 首次真人闭环先以微信公众号还是头条作为主验收平台；
5. 哪个真实主题作为用户本人第一次签字验收样本；
6. 真实发布何时单独授权；
7. 自动化账号何时从“用户确认选题”升级为“低监督运行”；
8. 第一个收入实验选择工具、服务、模板还是其他形态。

这些待决定项不得由实现模型自行假定为已确认需求。
