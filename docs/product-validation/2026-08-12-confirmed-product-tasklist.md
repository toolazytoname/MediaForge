## 0. 使用规则

这是一份实施任务树，不是开工授权。当前只完成文档固化，所有产品实现任务保持未勾选。

### 0.1 总顺序

```text
G0 规格签字
  ↓
G1 个人创作：输入 → 完整图文草稿
  ↓
G2 人工参与：局部/整体批注 → diff → 确认版本
  ↓
G3 成品与平台交付：阅读态 → 账号/渠道 → dry-run/草稿/导出
  ↓
G4 用户本人无说明真人验收
  ↓
G5 自动化创作账号
  ↓
G6 长期知识层、更多平台和受监督真实发布
```

没有通过前一闸门，不得用下一阶段的新功能掩盖当前主路径的问题。尤其不得先做更多平台、视频、数据大盘或无人值守发布。

### 0.2 每项任务的强制执行方式

用户正式授权后，每个任务都必须：

1. 在独立 worktree 中实施；
2. 先写能失败的测试，再做实现；
3. 独立 commit；
4. 开工前声明会改哪些文件；
5. 不修改 `pipeline/models.py`、SQLite schema、Adapter 签名或 TECH_SPEC 冻结契约；如确需改变，先写 RFC 并等待用户确认；
6. 不删除 sidecar、版本、审批、防覆盖和发布锁，只改变它们在产品中的展示层级；
7. 后端/API 测试、前端构建和“页面能打开”只算工程闸，不算产品通过；
8. 每轮重启真实 Web 服务，只用浏览器输入和点击走验收剧本；
9. 使用真实主题和真实材料，不用 mock 内容冒充真人验收；
10. 不触发真实发布，除非任务被标为高危、用户在场并另行明确授权。

### 0.3 全局完成定义

任何阶段只有同时满足以下条件才可勾选：

- 测试先红后绿，完整回归无新增失败；
- 前端生产构建通过；
- 浏览器无未处理控制台错误、无静默按钮、无全页上下文丢失；
- 用户输入、材料、正文和图片在刷新/失败后仍可恢复；
- AI 不静默覆盖正式正文或已选择图片；
- 没有伪造来源、流量数据、平台能力或发布回执；
- 任务的浏览器剧本有时间线、截图或录屏、输入和结果路径；
- 用户必须签字的产品闸门没有被模型代签。

## G1｜个人创作：一次输入到完整图文草稿

### [x] PF-01｜首页直接进入个人创作

- **目标**：访问 `/` 就看见个人创作输入区，用户无需理解内部导航。
- **用户可见结果**：
  - 一个主要输入区，接受主题和自己的描述/想法；
  - 一个明确主动作“生成文章”；
  - 图片、链接、PDF、Markdown 等参考入口；
  - 最近文章和自动化入口为次级，不抢主动作。
- **产品规则**：
  - 不再先选“我先写 / AI 先写”；点击“生成文章”就是一次明确 AI 授权；
  - 用户也可直接进入空白编辑器手写，但不把它做成进入前的模式问卷；
  - 标题、读者、平台、声音等高级信息可选，不得成为必填门槛。
- **测试先行**：根路由首要焦点、必填项不超过一个语义输入、键盘提交、防重复点击、刷新恢复草稿输入、旧项目存在时仍显示新建入口。
- **浏览器验收**：普通创作者打开首页，不听说明，输入 50—200 字真实想法并启动生成；主要点击数为 1。
- **非目标**：不在首页展示运行 stage、审批状态、研究完整度或平台账号配置。

  ✅ 完成于 2026-08-12，commit `e0366ef`，备注：首页以唯一想法输入和“生成文章”为主动作；真实浏览器验证了刷新恢复、Ctrl+Enter 一次创建并进入文章项目地址。

### [ ] PF-02｜多来源输入组件

- **依赖**：PF-01。
- **目标**：同一个创作输入支持主题/描述加可选资料。
- **首版资料类型**：
  - 图片上传；
  - URL；
  - PDF；
  - `.md` / Markdown 文本；
  - 直接粘贴的纯文本。
- **每项状态**：等待读取、读取中、已读取、需要确认、失败可重试、移除。
- **用户控制**：能预览资料名称/来源，能排除某项，不因一项失败而丢失全部输入。
- **来源规则**：保存原始来源、hash/时间和解析结果的可追溯关系；外部 URL 不可读时明确说明。
- **测试先行**：类型/大小拒绝、重复文件、同 URL、损坏 PDF、空 Markdown、图片元数据、路径穿越、部分成功、刷新恢复。
- **浏览器验收**：在一次创作中真实添加一张图片、一个 URL、一个 PDF 和一个 Markdown；故意加入一个坏链接，其他资料仍可用于生成。
- **首版边界**：资料默认只属于本篇文章；“保存到长期知识库”不在本任务实现。

### [ ] PF-03｜资料解析与可核查引用

- **依赖**：PF-02。
- **目标**：把可选资料转为 AI 能使用、用户能追溯的创作上下文。
- **行为**：
  - URL 提取正文、标题和来源；
  - PDF/Markdown/文本提取可引用段落；
  - 图片保留原图，并在需要时生成可审阅的说明；
  - 区分来源事实、作者观点、AI 推断和待核查项。
- **产品体验**：默认不强迫用户填写“声明数据库”；引用风险在文章和资料抽屉按需显示。
- **测试先行**：编码、超长文件、扫描 PDF 无文本、恶意 HTML、重定向/内网 URL 安全、来源丢失、引用定位、不可读取时不得声称已使用。
- **浏览器验收**：生成后能从文章中的关键引用回到对应资料；坏资料显示未使用，不阻塞起稿。
- **安全边界**：实现 URL 抓取前必须有 SSRF、超时、体积和 MIME 限制，不得直接信任用户提供路径。

### [ ] PF-04｜一次生成完整图文文章

- **依赖**：PF-01；PF-02/PF-03 可渐进接入，但无资料也必须可生成。
- **目标**：一次显式点击，生成标题、结构化正文、封面和上下文插图，形成可编辑 Markdown 文章。
- **生成结果**：
  - 不输出空白表单、研究板或 `[IMAGE: ...]` 占位；
  - 至少有一张封面；
  - 插图数量由文章长度和内容决定，首个验收样本使用两张；
  - 图片与具体段落关联并嵌入正文；
  - Markdown 能独立表达图片位置和替代文字。
- **生成过程**：在文章页显示真实阶段（正在理解资料、起草、准备图片等）及已完成部分；允许文本先出现、图片后补，但最终状态明确。
- **失败恢复**：
  - 文本失败：保留输入，可重试或进入手写；
  - 某张图失败：文章仍可编辑，只在该位置重试或换图；
  - 页面刷新：恢复任务和已经完成的内容；
  - 禁止重复点击创建多个不明项目。
- **测试先行**：无来源、有部分坏来源、文本成功图片失败、图片成功一半、provider 不可用、超时、重试幂等、断线恢复、成本审计、禁止静默覆盖已有正文。
- **浏览器验收**：用一个真实主题和真实材料，从首页一次点击；在同一页面看见完整可读文章、封面和两张上下文插图。记录总耗时和任何人工补救。
- **非目标**：不在这里生成所有平台版本或真实发布。

### [ ] PF-05｜文章本体工作区

- **依赖**：PF-04。
- **目标**：生成后“打开就是文章”，而不是切到 Project 驾驶舱。
- **默认界面**：
  - 中央是标题、封面、正文、插图；
  - 可直接编辑和阅读；
  - 资料、版本、视觉元数据、平台和交付检查放进抽屉/标签/更多；
  - 桌面与窄屏都不丢正文上下文。
- **保存**：自动保存或显式保存必须显示状态；失败不能丢内容；刷新恢复；保存形成可恢复版本。
- **图片交互**：选中图片可换图、修改、删除或查看详情；图片操作不跳出文章。
- **测试先行**：Markdown 安全渲染、光标和选择稳定、自动保存冲突、刷新、长文性能、图片加载失败、局部错误、撤销恢复、无障碍焦点。
- **浏览器验收**：连续编辑 10 分钟，期间刷新一次、制造一次图片错误；文章、光标附近内容和其他图片仍在。
- **明确隐藏**：固定 1—5 步、内部 ID、视觉圣经必填、锁按钮、审批 actor、stale 术语。

### G1 闸门

- [ ] 首页一眼可开始，主要点击一次；
- [ ] 主题 + 想法足以生成，不要求来源；
- [ ] 至少四种可选资料真实添加并有独立状态；
- [ ] 同一页面看见可编辑完整正文、封面和上下文插图；
- [ ] 任一局部失败不清空文章；
- [ ] 用户可以手动编辑、刷新恢复；
- [ ] 只用浏览器走通，未调用 API/CLI 替代输入和点击。

## G2｜人工参与：批注、diff 和版本确认

### [ ] RV-01｜整篇文章意见

- **依赖**：PF-05。
- **目标**：用户可以针对全文给出修改目标，不必自己拆成多个 prompt。
- **交互**：固定在文章旁的意见入口，显示作用范围为“整篇”；支持文字说明，可引用作者定位、读者或平台目标。
- **输出**：AI 只生成修改提案，不写回正式正文。
- **测试先行**：空意见、并发请求、重试、切页恢复、旧版本提案变 stale、provider 错误、成本记录。
- **浏览器验收**：输入“减少说教感，保留真实失败”，生成提案后正式正文保持不变。

### [ ] RV-02｜局部文本和图片批注

- **依赖**：PF-05。
- **目标**：用户选中标题、句子、段落或图片后，就地提出针对性意见。
- **文本锚点**：不能只保存字符偏移；正文改变后应能重定位或明确显示批注已失配，不能悄悄作用到错误段落。
- **图片锚点**：批注绑定图片 ID 和关联段落，支持构图、风格、主体、文字、事实性等意见。
- **可见性**：文章边缘显示批注标记和未处理数量，不用跳到研究/审批页面。
- **测试先行**：跨段选择、空选择、Markdown 标记、Unicode、正文变化后的锚点、删除段落、图片替换、多个批注、XSS。
- **浏览器验收**：选中一段提出改写意见；再选中封面提出换图意见；两条批注位置准确，刷新后仍在。

### [ ] RV-03｜双栏 diff 提案

- **依赖**：RV-01、RV-02。
- **目标**：以 Beyond Compare / Git diff 心智展示 AI 修改。
- **界面**：
  - 左侧当前正式版本；
  - 右侧建议版本；
  - 行内或块级显示新增、删除、替换；
  - 能看见本次意见、范围、涉及图片和事实风险；
  - 同步滚动和长文定位。
- **用户操作**：编辑右侧建议稿、接受、拒绝、返回文章；首版按 DOC-02 决定是否支持逐块接受。
- **测试先行**：标题/段落/列表/图片链接 diff、超长文章、并发正文修改、stale 提案、右侧手动编辑、拒绝无副作用、接受生成新版本。
- **浏览器验收**：对一段和整篇各生成一次提案；用户能不看说明指出哪里删了、哪里增加了。

### [ ] RV-04｜确认、撤销和版本历史

- **依赖**：RV-03。
- **目标**：确认修改后得到新正式版本，任何一次接受都可恢复。
- **后台复用**：优先复用 Master/Visual/Variant 版本链、suggestion 和原子写，不新增另一套互相冲突的版本系统。
- **行为**：
  - 接受时校验基础版本；
  - stale 时禁止静默套用，提供重新比较；
  - 拒绝不改变正文；
  - 恢复旧版本本身也产生新版本；
  - 历史面板是次级能力。
- **测试先行**：并发接受、重复点击、stale、拒绝、恢复、历史上限、异常写入、正文与图片一致性。
- **浏览器验收**：拒绝一次确认正文不变；接受一次确认新版本出现；恢复前一版成功。

### [ ] RV-05｜上下文换图与图片版本

- **依赖**：RV-02、RV-04。
- **目标**：针对文章里的封面/插图生成修改候选并比较，不进入独立“视觉计划”流程。
- **行为**：保留原图、显示候选、可基于原图编辑、可重新生成、选择后更新文章引用；失败记录和预估成本在详情中可查。
- **测试先行**：未知引用、provider 未配置、生成失败审计、路径安全、候选选择、取消、旧候选、图片位置不变、Markdown 同步。
- **浏览器验收**：对一张真实图片提意见，生成候选，先拒绝再选择另一候选；原图可恢复，正文其他部分不变。

### G2 闸门

- [ ] 全文和局部都能提出意见；
- [ ] 文本与图片锚点准确且可恢复；
- [ ] AI 修改先以 diff 呈现，正式版本不被静默覆盖；
- [ ] 用户能手动调整建议稿；
- [ ] 接受、拒绝、恢复均由浏览器真实走通；
- [ ] 版本和审计能力在后台保留，但没有重新占领文章首屏。

## G3｜成品、平台版本、账号与安全交付

### [ ] DL-01｜最终阅读态与 Markdown 导出

- **依赖**：G2。
- **目标**：点击“确认最终稿”后首先看见一篇完整文章。
- **阅读态**：标题、摘要、封面、正文层级、引用、行内图片、作者信息和必要的 AI/来源标识；加载、失败、重试、返回编辑明确。
- **导出**：
  - Markdown 为正式一级导出；
  - 本地图片路径/打包策略明确，导出的 Markdown 可重新打开；
  - HTML、图片包、ZIP 放在“下载与备份”；
  - ZIP 不得成为主按钮。
- **测试先行**：安全渲染、相对图片路径、中文文件名、重复导出不覆盖、版本命名、下载中断、导出包校验。
- **浏览器验收**：打开最终文章并导出 Markdown；在仓库外的临时目录打开，正文和图片关系仍可识别。

### [ ] DL-02｜一次生成平台原生版本

- **依赖**：DL-01。
- **首版平台**：微信公众号和今日头条。
- **目标**：一个动作基于最终主稿同时准备两个独立平台版本。
- **体验**：平台标签直接显示可读预览；需要时进入编辑；主稿和两个平台稿相互独立；主稿后来变化时只在有风险时提示合并。
- **平台差异**：标题、摘要、结构、开头钩子、图片规格、引用和平台限制按平台适配，不机械复制。
- **测试先行**：双版本部分失败、幂等、独立编辑、选中图片引用、stale、恢复、平台稿不覆盖主稿、Markdown/HTML 安全。
- **浏览器验收**：一次点击出现微信和头条；分别修改一句，刷新后互不覆盖；默认展示文章预览而非 disabled textarea。

### [ ] DL-03｜账号、渠道和能力矩阵

- **依赖**：DL-02。
- **目标**：在交付页选择真实配置的账号，并清楚看见平台、渠道、账号和支持能力。
- **能力字段**：草稿箱、立即发布、平台原生定时、图片上传、预览回执、所需账号资质、当前授权健康。
- **数据来源**：实现时只依据平台官方文档、真实账号和已验证适配器；无法确认的能力显示“待验证”。
- **凭据安全**：密钥/cookie/中转配置只保存到本地 gitignored secrets 或环境变量；UI 绝不回显明文；文档和日志不写私有地址。
- **测试先行**：无账号、过期账号、同平台多账号、能力未知、密钥脱敏、非法平台、权限不足。
- **浏览器验收**：用户能看出“哪个账号、哪个渠道、可以做什么”，而不是只看内部 account ID。

### [ ] DL-04｜平台原生定时选择

- **依赖**：DL-03。
- **目标**：只在平台真实支持时提供原生定时选项，把时间作为平台发布参数，而不是创建 MediaForge 本地 cron。
- **体验**：显示平台时区、允许时间范围、账号限制、最终平台回执；不支持的平台不显示伪定时选项。
- **测试先行**：时区、夏令时、过去时间、平台最早/最晚限制、能力未知、接口拒绝、重试幂等、不得创建本地定时任务。
- **浏览器验收**：选择支持原生定时的平台和账号，设置时间后 dry-run/请求预览明确显示将传给平台的字段；检查本地没有创建 cron 或后台调度任务。
- **待验证风险**：旧 `bucket_week()` 的 UTC 日历分桶问题应在涉及排期 UI 时单独解决或明确隔离。

### [ ] DL-05｜交付检查和 dry-run

- **依赖**：DL-02、DL-03。
- **目标**：把底层 Approval 变成一次清晰的交付确认，而不是创作过程中的审批驾驶舱。
- **自动检查**：缺图、坏链接、待核查事实、平台稿 stale、账号能力、标题/正文限制、AI 标识、版权风险。
- **人工确认**：用户看完最终预览后一次确认；审计 actor、逐项备注和历史藏在详情。
- **动作**：安全导出、复制、草稿箱 dry-run；不得创建真实发布副作用。
- **测试先行**：stale 阻断、重新检查、重复确认、真实 actor、无 publication 副作用、防覆盖导出、错误局部显示。
- **浏览器验收**：从文章完成态选择账号和渠道，完成检查，进入 dry-run/草稿交付；能看见明确回执，数据库和平台均无真实发布。

### [ ] DL-06｜真实发布 RFC（高危，只写 RFC）

- **依赖**：G4 用户本人验收通过。
- **目标**：在写任何真发实现前，逐平台说明官方/扩展/浏览器通道、原生定时能力、幂等、回执、失败恢复、账号和风控。
- **输出**：RFC、威胁模型、平台能力证据、单条试发剧本、停止条件和回滚方案。
- **红线**：本任务只写 RFC，不开 `publish.enabled`，不加白名单，不真实发布。

### [ ] DL-07｜单平台单账号真实发布验证（高危、用户在场）

- **依赖**：DL-06 获用户单独批准。
- **目标**：只对一个平台、一个账号、一篇用户确认的文章做一次真实交付。
- **安全条件**：`publish.enabled=true`、平台白名单、用户最终确认、三重锁、防重复、意图日志和回执全部生效。
- **验收**：平台侧确有草稿/发布/原生定时结果；失败不会自动重复发；用户确认实际效果。
- **红线**：不能自动扩到第二个平台或第二篇；任何账号风控迹象立即停止。

### G3 闸门

- [ ] 最终结果首先是一篇文章；
- [ ] Markdown 导出可用，ZIP 仅备份；
- [ ] 微信和头条版本一次生成、独立编辑；
- [ ] 平台、渠道、账号和能力清晰可见；
- [ ] 原生定时与本地调度概念严格分开；
- [ ] dry-run/安全交付没有真实发布副作用；
- [ ] 真实发布仍未开始，除非 DL-07 被单独授权。

## G4｜用户本人真人验收

### [ ] VA-01｜个人创作黄金路径

- **验收者**：产品所有者本人；模型不能代签。
- **输入**：一个本人真实想写的主题、50—200 字想法，至少一张图片、一个链接、一个 PDF 或 Markdown 中的两种。
- **仅浏览器步骤**：
  1. 打开首页；
  2. 输入想法和参考；
  3. 点击生成；
  4. 阅读完整图文草稿；
  5. 手动改一处；
  6. 对一段和一张图分别批注；
  7. 审查 diff，拒绝一次、接受一次；
  8. 确认最终稿；
  9. 生成微信/头条版本并分别编辑；
  10. 查看账号/渠道/原生定时能力；
  11. 导出 Markdown；
  12. 停在 dry-run 或安全交付，不真实发布。
- **记录**：总耗时、主点击数、等待、离开工作台次数、失败恢复、人工修改比例、愿不愿署名、最难用的三点。
- **通过标准**：用户无需说明完成，明确表示“我知道怎么用，而且愿意继续用”。

### [ ] VA-02｜对抗性浏览器验收

- **目标**：专门尝试让主路径失败。
- **场景**：坏 URL、损坏 PDF、超大文件、模型超时、图片失败、断网、刷新、重复点击、正文并发变化、stale diff、账号过期、平台能力未知、导出同名、旧前端 chunk。
- **通过标准**：不丢输入、不静默、不全页消失、不重复生成/发布、不泄漏 secret；每个错误都在发生位置提供恢复动作。

### [ ] VA-03｜四周真实自用实验

- **依赖**：VA-01。
- **目标**：证明它不是只能演示一次。
- **样本**：至少完成 4 个真实主题；不强制周更，可按灵感发生，但实验最长四周。
- **指标**：
  - 从输入到首稿时间；
  - 总创作时间；
  - 人工修改比例；
  - 批注/接受/拒绝次数；
  - 图片重做次数；
  - 离开 MediaForge 的次数和原因；
  - 实际导出/草稿/发布结果；
  - 用户是否再次主动打开；
  - 内容质量、价值观和署名意愿。
- **通过标准**：用户至少两次主动复用；产品确实减少重复劳动；没有因为自动化牺牲真实感或安全。

### G4 闸门

- [ ] VA-01 由用户签字通过；
- [ ] VA-02 无 P0/P1 阻塞问题；
- [ ] VA-03 证明产品有重复使用价值；
- [ ] 只有通过后，才允许自动化账号和真实发布成为主优先级。

## G5｜自动化创作账号

### [ ] AU-01｜创作账号画像

- **依赖**：G4。
- **目标**：建立一个专注赛道的 AI 创作账号配置，而不是把个人路径加满自动化开关。
- **配置**：账号定位、典型读者、内容支柱、作者身份、事实来源、价值观红线、语气、目标平台、允许自主的步骤、预算和停止条件。
- **首个默认画像**：普通人的 AI 工作与增收实验室；须由用户确认后启用。
- **测试先行**：严格配置、版本、未知字段、不可变更新、secret 隔离、价值观红线不可被普通 prompt 覆盖。
- **浏览器验收**：用户能用普通语言看懂并修改账号定位，不暴露模型参数和内部 stage。

### [ ] AU-02｜候选选题发现

- **依赖**：AU-01。
- **目标**：从可信外部来源、已有素材和真实生活记录中发现候选选题。
- **来源要求**：记录来源、时间、原始信号和可核查性；不能把模型常识伪装成实时趋势。
- **成本/频率**：受预算限制，允许手动触发和低频自动发现；不默认 24 小时抓取所有平台。
- **测试先行**：重复选题、来源失效、时效、无数据、抓取失败、预算上限、隐私资料隔离。
- **浏览器验收**：至少五个候选都有真实来源和“为什么现在”，无来源的明确标记为推测。

### [ ] AU-03｜选题决策卡

- **依赖**：AU-02。
- **目标**：为“流量、爆款、价值、价值观”提供可判断信息。
- **字段**：时机、流量证据、读者痛点、钩子、读者价值、账号匹配、独特角度、价值观风险、竞争/窗口、制作成本、AI 建议、置信度、反方理由、待确认事实。
- **用户动作**：开始创作、调整角度、稍后、放弃。
- **测试先行**：缺失指标不得补零或造数、过时数据、互相冲突来源、置信度依据、价值观阻断、操作幂等。
- **浏览器验收**：用户只看决策卡，能说明为什么选/不选；系统不强迫用户信 AI 排名。

### [ ] AU-04｜决策学习与审计

- **依赖**：AU-03。
- **目标**：从用户选择和理由提出偏好更新。
- **安全规则**：AI 只能提出“学到的偏好”；用户确认后才写入账号画像；每次变化可查看、撤销。
- **测试先行**：误学一次选择、敏感信息、未确认写入、撤销、冲突偏好、历史上限。
- **浏览器验收**：放弃一个选题并说明原因，系统提出合理学习；用户拒绝后账号画像不变。

### [ ] AU-05｜自动选题复用个人创作引擎

- **依赖**：AU-03、G1—G3。
- **目标**：被批准的选题直接进入与个人创作相同的文章、图片、批注、diff、平台和交付路径。
- **原则**：不复制另一套自动化编辑器；自主程度决定哪些显式确认可暂缓，不改变数据安全和可恢复性。
- **测试先行**：用户接管、自动任务暂停、预算耗尽、来源失效、正文版本、失败恢复、无静默发布。
- **浏览器验收**：从一张选题卡点击“开始创作”，进入同一文章工作区；用户随时可人工修改和停止。

### [ ] AU-06｜低监督试运行

- **依赖**：AU-05、VA-03。
- **目标**：让一个账号在受控周期内自动发现和准备内容，用户只做关键决策。
- **第一阶段权限**：可发现、研究、生成草稿和平台预览；不可真实发布。
- **观测**：每一步、来源、成本、失败、AI 判断和用户接管可见；异常暂停而不是无限重试。
- **验收**：连续两周产生可审阅候选和草稿；没有伪造数据、越过价值观或产生发布副作用；用户认为决策信息足够。

### [ ] AU-07｜无人值守发布 RFC（未来高危）

- **依赖**：AU-06、DL-07 多次稳定、用户单独授权。
- **目标**：定义哪些账号、平台、内容类型和风险等级可无人值守，以及熔断、预算、速率、重复、风控和人工召回。
- **红线**：只写 RFC；未经后续逐项授权不得实现或启用。

## G6｜长期知识层、商业验证和平台扩展

### [ ] KB-00｜长期知识库 RFC

- **依赖**：G4；不得阻塞个人创作。
- **目标**：把“Raw → Wiki → Article Project”写成独立 RFC。
- **必须决定**：目录/存储、不可变来源、页面类型、frontmatter、引用、矛盾、更新、删除/更正、隐私、权限、与 `writing-materials` 的迁移关系。
- **验收**：用户确认边界；明确当前尚未建设，不能把已有 Markdown 文件夹包装成完成的知识系统。

### [ ] KB-01｜不可变 Raw 摄取

- **依赖**：KB-00。
- **目标**：把文章链接、PDF、Markdown、图片和笔记作为可追溯原始来源摄取。
- **要求**：hash、来源、时间、版权/隐私、解析版本、失败状态；原始内容不被 AI 静默改写。
- **测试先行**：重复、变更 URL、文件替换、删除请求、私密来源、路径安全、超限和部分失败。

### [ ] KB-02｜Wiki 编译和维护

- **依赖**：KB-01。
- **目标**：AI 创建/更新实体、概念、来源、综合和对比页面，维护 WikiLinks、来源和矛盾。
- **用户控制**：所有知识更新可审阅、可撤销；不确定内容明确标记。
- **测试先行**：交叉引用、矛盾、孤立页、重复实体、过时来源、并发更新、不可逆覆盖。

### [ ] KB-03｜创作中检索和引用

- **依赖**：KB-02、PF-02。
- **目标**：个人创作输入可搜索知识库并将页面/来源附到当前文章。
- **原则**：检索结果必须回到来源；知识库只是增强，不成为开始创作的门槛。
- **浏览器验收**：从首页搜索一个已有概念，附到文章并在引用中回溯；不选知识库也能正常生成。

### [ ] KB-04｜把确认过的创作洞察回写知识层

- **依赖**：KB-02、RV-04。
- **目标**：文章、批注和发布复盘中产生的可复用洞察可提议写回 Wiki。
- **红线**：未经用户确认不自动把文章观点升级为长期事实；平台数据与作者判断分层保存。

### [ ] BI-01｜内容—产品组合地图

- **依赖**：G4。
- **目标**：梳理用户持续维护的产品、对应真实需求、可写主题、潜在读者和可能的商业形态。
- **原则**：不强行合并产品；不写用户没有真实使用的推荐；MediaForge 作为首要 dogfooding 样本。
- **输出**：内容支柱、产品证据、读者问题、可验证的 CTA，不承诺收入。

### [ ] BI-02｜首个小额收入实验

- **依赖**：BI-01、真实内容有基础读者反馈。
- **目标**：选择一个用户真正使用的工具、服务或内容产品，验证是否有人愿意付费。
- **指标**：有效咨询、试用、付费、交付成本和复购意向，不以阅读量替代收入。
- **红线**：不承诺“月入几千”；不制造焦虑或伪造客户反馈。

### [ ] PL-01｜首批平台官方能力矩阵

- **依赖**：G4。
- **目标**：按官方文档和真实账号核实微信公众号、头条，以及一个由数据选出的候选平台。
- **字段**：内容格式、图片、草稿、立即发布、原生定时、账号资质、AI 标识、限频、回执和 API/扩展限制。
- **要求**：实现时必须重新查阅当前官方资料；能力可能变化，不使用旧记忆拍板。

### [ ] PL-02｜基于证据选择第三个平台

- **依赖**：PL-01、VA-03。
- **目标**：根据实际读者、内容表现、创作成本、账号能力和商业价值，在知乎、小红书、Bilibili、视频号等候选中只选择一个下一步。
- **验收**：有明确“为什么是它、为什么不是其他平台”的证据；不因平台数量好看而扩张。

### [ ] PL-03｜视频路线重新立项

- **依赖**：个人图文闭环稳定、第三平台决策或明确视频需求。
- **目标**：重新评估视频是否复用文章、脚本、图片和平台适配，而不是继续旧数字人功能堆叠。
- **红线**：在此之前不把 M12 旧视频能力拉回创作者主路径。

## 7. 横切任务

### [ ] QA-01｜浏览器 E2E 基础设施

- **目标**：把真人关键动作自动化为防回归测试，但不代替用户验收。
- **覆盖**：真实服务启动、旧 chunk 恢复、首页输入、附件、生成状态、编辑、批注、diff、换图、平台预览、导出、dry-run。
- **要求**：关键产品任务必须有浏览器测试；测试使用隔离项目目录和可控 provider，真实 provider 另设人工 smoke。
- **红线**：不得只用直接 API 调用伪装用户路径。

### [ ] QA-02｜真实 provider smoke 套件

- **目标**：验证用户本地配置的 OpenAI-compatible 文本和 GPT Image 2 通道，不泄漏 secret。
- **范围**：最小文本生成、单张图片生成、图片编辑、超时和错误映射；结果有成本/模型审计。
- **安全**：默认不在全量 CI 中消耗真实额度；由用户显式触发；日志脱敏；不记录私有中转地址。

### [ ] QA-03｜可用性与无障碍

- **目标**：保证长文编辑、批注和 diff 在常见屏幕、键盘和中文输入法下可用。
- **覆盖**：焦点、选区、快捷键、颜色对比、屏幕阅读标签、窄屏、长文性能、图片占位、错误通知。
- **浏览器验收**：不使用鼠标完成一次保存/批注/接受；在窄屏阅读和修改一段文章。

### [ ] SEC-01｜输入和渲染威胁模型

- **目标**：覆盖 URL 抓取、PDF/Markdown/图片解析、HTML 渲染、文件路径、提示注入和隐私泄漏。
- **要求**：SSRF 防护、MIME/体积/页数限制、沙箱/超时、Markdown 消毒、路径 jail、来源内容与系统指令隔离。
- **验收**：对抗样本不会访问内网、读取工作区任意文件、执行脚本或泄漏 secret。

### [ ] SEC-02｜发布与原生定时安全

- **目标**：确保平台账号、立即发布和原生定时不绕过既有安全边界。
- **覆盖**：三重锁、防重复、意图日志、账号白名单、平台时间参数、失败不重发、回执核对、用户撤销能力。
- **红线**：必须在任何真实发布任务之前通过。

### [ ] OBS-01｜创作过程可观测性

- **目标**：记录用户真正关心的进度和失败，不把内部 stage 泄露成产品导航。
- **记录**：生成耗时、provider/模型、资料使用、成本预估、重试、版本、图片候选、平台动作和错误恢复。
- **隐私**：默认不记录正文全文到普通日志；敏感信息脱敏；用户可查看并清理项目审计数据。
