# MediaForge 真实流程验收用例

日期：2026-09-10。用途：交给另一个模型从用户视角走查，不是继续补单元测试。

## 给执行模型的任务

请执行下方 T01–T08，逐项报告 PASS / FAIL / BLOCKED / NOT RUN。先记录问题和证据，本轮不要边验收边改代码。修好后重测必须另列结果，不能抹掉首次失败。

先读 AGENTS.md 和本轮唯一任务入口 `docs/CREATOR_OPERATIONS_TASKS.md`。最近修复验证见 `docs/product-validation/review-04-regression.md`；历史 1950 passed 不能代替本次真实验收。

- 从浏览器开始，正常用户流程必须通过页面完成。找不到入口、按钮无效、必须写脚本才能继续，都算产品问题。API/数据库只用于核对证据，不能绕过 UI 后把用户流程标为通过。
- 真实写稿、生图、改图必须使用已有 BYOK 配置；模型列表成功、占位文字、导入本地图不能代替真实生成。记录实际请求模型，不展示 key、cookie 或完整认证请求。
- 新建带 `验收-日期-用例编号` 前缀的作品。保留 `prj_a63f79b2`、现有草稿和未跟踪截图，不覆盖用户作品。
- 默认平台交付测试到草稿箱，不公开发布、不群发。公开发布另见附录；不要把开发授权当作任意文章发布授权。沿用用户已明确授权的账号、付费额度和操作范围，不重复索要已给过的授权；未授权部分标明依赖，继续其他用例。
- 正常流程用真实服务；故障注入只在独立测试实例与临时账号/作品目录进行。不要断开用户生产网络、修改全局凭据或杀掉仍有真实请求在途的服务。
- 基准地址为 `http://127.0.0.1:8788/`，以实际配置为准。上轮修复后未重启服务：先确认运行进程加载的代码版本；如需重启，先核对在途任务和已启用计划，避免无意触发运营。

推荐顺序：T01–T04 共用一篇个人作品；T05 另建隔离作品；T06 另建一篇运营作品；T07–T08 使用独立实例。没有第二个真实账号时，如实拆分“本地隔离验证”和“平台账号隔离未验收”。

## 共用材料

可直接用以下材料开始，避免模型擅自替作者编经历：

> 想法：我想写给刚开始用 AI 写公众号的人：AI 起草很快，但核对事实与保留自己的观点更重要。
> 我的观点：AI 可以帮助组织表达，作者仍须对具体事实和结论负责。
> 写作动机：给第一次用 AI 写文章的人一个能照做的工作顺序。
> 个人经历：本轮不提供个人故事，请不要补写“我曾经……”的经历。
> 风格：平实、具体，少口号，明确区分来源事实与作者判断。

执行者找 2–3 篇可打开的相关公开资料，记录标题、URL、读取时间和实际引用片段。不要拿不可访问页面或只有书名的材料充当已读全文。不采用虚构统计数字。

## T01｜从首页开始，访谈后写出可审阅主稿

**目的：**验证新手能否知道从哪里开始，并保留作者表达权。

**步骤：**
1. 用桌面浏览器打开首页，不先查 API。记录 30 秒内能否找到“开始创作”“作品”“账号”“设置”。
2. 点击“开始创作”，输入共用材料中的想法，先不填写其余信息。
3. 观察系统如何获取观点、动机和经历；补充剩余共用材料与来源，确认写作方向。
4. 请求 AI 初稿，等待时尝试再次点击一次，观察按钮和请求数。
5. 阅读建议，先不接受；检查主稿是否保持原状。然后将建议放入编辑器，修改一句话并保存，刷新页面。

**通过标准：**
- 用户无需理解 pipeline / gate / run；缺少的作者信息被明确询问，或以清晰可填写项呈现。若只有表单，另记“对话式访谈尚未实现”，不要称作 AI 已主动访谈。
- 使用真实文本模型，输出有主题、有来源依据、不虚构个人经历；建议未接受前不改主稿。
- 重复点击不产生第二次起稿请求；保存和刷新不丢修改。
- 记录从开始到可审阅主稿的时间，以及每个“我不知道下一步点什么”的位置。

**证据：**入口、访谈、建议与保存后页面截图；project_id；主稿版本；脱敏请求与用量记录。

## T02｜三张真实配图、一次原图编辑与图文预览

**前提：**T01 主稿已保存，图片模型为配置中的 GPT Image 2。

**步骤：**
1. 在作品内建立 1 张封面和 2 张正文插图，分别填写用途、画面方向和对应段落，保存计划。
2. 逐张生成候选；生成期间再点一次生成，记录是否被禁用。查看缩略图与放大图，选择三张图片。
3. 对其中一张点“基于此编辑”，要求“保持主体和整体构图，调整背景色并减少装饰元素”。
4. 对比原图和新图，选择新版；刷新页面并打开主稿/平台图文预览。

**通过标准：**
- 三张图来自真实生图请求，编辑请求确实携带原图；不是重新生成后口头声称编辑成功。
- 缩略图、放大图和已选择状态一致，图片与各自段落相关；刷新后仍可见。
- 原图保留，新图有独立版本；编辑失败也不丢原图。
- 预览能看到正文中的图片，不只是资产列表有图片。若需要手动插图，记录步骤和操作成本。
- 费用有可追溯估算；未定价不能显示免费。记录成功请求数、未知请求数及可核对费用。

**证据：**三张图与编辑前后对照；asset_id、版本、实际模型、原图引用；包含正文插图的预览截图。

## T03｜独立平台稿、版本恢复和过期审批

**步骤：**
1. 从主稿创建微信公众号和头条两个平台版本，各自修改标题和一段正文，保存。
2. 修改主稿并保存，检查两个平台稿是否被覆盖，是否提示上游更新。
3. 按页面引导合并需要的修改，确认已合并当前主稿；恢复一个旧版本，验证恢复形成新版本。
4. 锁定并完成测试内容包审阅。审批人如为执行模型，记录为“验收代理”，不得冒用用户署名认可。
5. 再修改一份平台稿，尝试按旧审批交付；随后通过页面重新检查并审阅。
6. 以 390×844 左右的移动视口打开同一作品，编辑、保存、查看图片并返回“今天”。

**通过标准：**
- 主稿、微信稿、头条稿互不静默覆盖，历史可恢复。
- 修改后的内容不能沿用旧审批发送；重新审阅路径可见、可完成。
- 手机下主要按钮可见可点，编辑区不被侧栏或弹窗挤没，无妨碍操作的横向溢出。

**证据：**三份版本号与差异；恢复前后版本；旧审批被拦截截图；手机截图。

## T04｜真实送入公众号草稿箱，并核对是否重复

**前提：**使用已授权的真实公众号，明确绑定账号，T03 当前版本已审阅，交付开关允许草稿。

**步骤：**
1. 在作品中核对账号名称、要送出的版本和交付方式，点击“送到草稿箱”。
2. 等待期间再次点击一次；成功后刷新页面再尝试同一版本的相同动作。不要创建新版本或改账号来绕过幂等。
3. 打开该公众号后台草稿箱，按验收标题找到文章，实际打开编辑器。
4. 核对标题、正文、封面、两张插图及插图位置，检查是否出现多份重复草稿。

**通过标准：**
- 后台确实存在目标文章，图文完整，账号正确；有对应 media_id/交付回执。
- 同一作品、版本、账号与审批下重复动作不新增第二份草稿。
- 系统只标记“草稿成功”，不标记“已公开发布”。
- 权限/IP 白名单/登录问题应显示具体原因和下一步，文章和图片保留；没有后台可见证据不能写 PASS。

**证据：**项目交付结果；公众号后台文章和草稿列表截图；media_id；重复动作前后记录数。

## T05｜两个账号不串用，头条能否从页面真实交付

**步骤：**
1. 配置同平台账号 A/B，使用可区分的名称、定位和风格。新建两个验收作品，先检查未绑定作品是否要求明确选择账号。
2. 分别绑定 A/B，刷新页面，核对归属；查看其中一个作品是否会默认切到第一个账号。
3. 若两个真实账号均已连接且获授权，各送一份带不同标题的草稿，分别登录后台核对；否则只完成本地归属检查，远端部分标 BLOCKED。
4. 对头条，在作品页面查找草稿交付入口，连接已授权账号后尝试保存真实草稿，并到头条创作后台打开核对。

**通过标准：**
- A/B 的作品归属、凭据引用和发送目标互不串用，未绑定不擅自选择 A。
- 头条草稿必须能在平台后台找到，图片与正文完整。
- 如果作品页只有 Markdown/ZIP 导出或写着“只支持预览”，记为 **FAIL：用户交付入口未打通**；可另记 API 能力，不得用脚本发成功掩盖这个失败。

**证据：**账号绑定截图、两边后台核对记录；头条入口及后台草稿。不要截出凭据。

## T06｜账号排期真实产生一篇完整图文

**前提：**新建专用验收账号档案，交付目标明确为草稿；用用户已授权的预算和启停范围，不改其他账号。

**步骤：**
1. 从账号页面填写定位、读者、风格和真实参考资料，设置一次即将到期的计划，检查“今天”是否显示下一次执行。
2. 如 UI 不能选近期时间，记录限制；按它实际支持的最近时间等待，或将时间控制作为独立调度测试，不能修改数据库后宣称正常排期体验通过。
3. 到期后观察系统自动研究、写稿、配图和适配。不要人工调用单独生成函数替它补齐缺失阶段。
4. 合格时检查授权规则版本、机器质量结果及草稿回执；不合格时从“今天”查看原因和恢复入口。
5. 完成本次验收后，将专用账号运营恢复到验收前状态，核对没有遗留待发任务。

**通过标准：**
- 实际定时驱动创建一个任务和对应作品，使用真实文本与图片服务，产出封面和两张插图。
- 文章有参考依据、符合账号定位，不重复拼接主题、不编造账号作者经历；最终稿可以审阅。
- 自动交付使用账号授权和质量记录，不伪装为作者逐篇批准。
- 不合格或失败时停止交付，保存已完成成果并出现可理解的待办。
- 此用例只有真实走到草稿后台才算整条链路 PASS；中途暂停可以记“异常处理通过、完整运营链路未通过”。

**证据：**账号计划、触发时间、job_id、project_id、阶段记录、来源、实际调用和费用、质量记录及后台草稿。

## T07｜已有正文恢复，与活跃任务不被重复接管

**执行方式：**独立实例的故障模拟，不能在用户生产请求在途时强行重启。

**步骤：**
1. 用临时验收作品走到“主稿已保存，图片未齐”；在阶段边界暂停独立实例并保留其 SQLite 和 sidecar，重新启动。
2. 从用户可用的恢复入口继续，记录主稿版本、图片槽位和模型调用数。
3. 另一次运行中，让一个写稿请求处于等待状态；同时从第二个客户端触发运营检查。只对临时实例在外部请求边界使用阻塞替身，保留真实任务、文件锁及存储逻辑。
4. 取消另一个临时任务，再触发检查，查看是否又开始生成或交付。

**通过标准：**
- 已有主稿被复用，无 UnboundLocalError，无静默重写；只补缺失图片，任务能继续到既定终点。
- 第一执行器活跃时，第二执行器不再次调用写稿/生图，不把原任务误标失败。
- 进程退出后锁可释放，遗留任务能恢复；已取消或完成任务不重跑。
- 若后台恢复正确但用户没有可用恢复入口，分别记录“后端通过、UI 恢复失败”。

**证据：**恢复前后相同 project_id/主稿版本；槽位及调用数；两客户端时间线；任务终态。注明使用了哪些替身。

## T08｜质量不合格与预算不足时确实停止

**执行方式：**临时作品与账号；质量检查和预算持久化保留真实实现。

**步骤：**
1. 保存一份正常主稿和平台稿，再将主稿改为“未经核实的短文”；触发自动恢复，观察是否重新质检。
2. 恢复正常主稿，只将微信平台稿改成该短文，再试一次。
3. 在另一份待配图作品上，将专用账号可用预算设为低于一张图的已配置估价，触发自动配图。
4. 增加该测试账号预算到允许范围后，通过支持的恢复路径继续。独立测试实例可使用计数型图片替身，以证明拦截发生在外部调用之前。

**通过标准：**
- 两种坏稿都不获得默认 pass/8，也不交付；正文原样保留，页面引导修改。
- 预算不足时图片接口调用数为 0，未生成的图片不计作已消费；不是请求发出后才报预算不足。
- 预算恢复后可以继续；已生成图片和已结算费用不重复登记。
- 如果“重试”入口只隐藏异常、不恢复任务，记为 FAIL。

**证据：**修改前后稿件版本、实际质量记录、交付调用数、预算及 reservations/settled 变化、图片接口调用数。

## 附录：不确定结果与公开发布的补充验收

以下属于故障注入或单独授权后的扩展，不要为了制造故障对真实账号盲目发送。

| 场景 | 如何执行 | 必须得到的结果 |
| --- | --- | --- |
| 图片已落盘、资产登记失败 | 独立实例中仅让登记步骤报错，再恢复 | 复用同一文件，补登记与结算；不再请求同一张图 |
| 图片请求超时，是否计费未知 | 在图片 provider 边界返回超时，再触发恢复 | 保留请求意图和预算预留，不自动发第二次请求；不能显示免费或生成成功 |
| 草稿转公开发布被明确拒绝 | 独立实例用明确权限拒绝响应；恢复后显式重试 | 原意图被最终失败回执闭合；第二次可发起，成功后重复点击不再发送 |
| 公开发布已受理但查询失败 | 模拟收到 publish_id 后查询报错，再恢复查询 | 保存 publish_id，状态仍 unknown；只查询，不重新 submit |
| 真实公开发布 | 仅在已有明确的账号、文章版本和发布授权时执行；缺少则 NOT RUN | 平台真实成功回执和公开页面均可核对，不能将“发布中”或 media_id 当成成功 |

## 交付报告格式

将结果写入新的 `docs/product-validation/real-flow-results-<日期时间>.md`，截图放同名目录，避免覆盖本用例和历史证据。

| 用例 | 状态 | 操作路径与耗时 | 作品/任务/资产/回执 ID | 证据路径 | 卡点或外部依赖 |
| --- | --- | --- | --- | --- | --- |
| T01–T08 分别填写 | PASS / FAIL / BLOCKED / NOT RUN | UI 与 API 辅助操作分开写 | 不含凭据 | 截图/脱敏日志 | 不写笼统“基本可用” |

结尾只回答：
1. 个人创作到公众号草稿箱是否真正跑通？耗时多少？
2. 头条、多账号和自动运营分别验证到哪一步？哪些还没通过？
3. 最妨碍新手的三个操作点是什么？给出具体页面和改进建议。
4. 付费调用、未知结果、残留计划各有多少？专用验收账号是否恢复原状态？

本轮只产出报告；不要因单次顺利就勾选四周真人实验或替作者作最终署名决定。
